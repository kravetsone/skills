# Deliverables — exact formats

Five artefacts. Each has required sections; `plan-lint.mjs` and `coverage-report.mjs` check for them. Skeletons live in `templates/`.

Write prose in the language of the source spec. Identifiers, table names, endpoint paths, event names and error codes stay English regardless.

---

## 1. `BACKEND-PLAN.md` — the main document

Template: `templates/backend-plan.md`. Required sections, in order:

1. **Summary** — what is being built, in five sentences, for someone who has read neither the spec nor Figma.
2. **Sources** — which documents and Figma files, with fetch dates and hashes. States what was *not* available.
3. **Open questions** — anything still unresolved at emission time. An empty section is suspicious; a plan with no open questions usually means somebody guessed.
4. **Domain model** — entities, identity, lifecycles, and the invariants as sentences.
5. **Data model** — tables, constraints (each mapped to an invariant), indexes (each mapped to a query).
6. **API contract** — the endpoint table, for `--mode api` and `--mode both`.
7. **Bot contract** — commands, callbacks, scenes, for `--mode bot` and `--mode both`.
8. **Concurrency register** — the `H-###` table with guards. See [race-conditions.md](race-conditions.md).
9. **Background work** — tasks, schedules, retry and DLQ policy, flow control.
10. **Configuration** — the env var table, marking which are new to CI.
11. **Observability** — spans, metrics, the alert thresholds.
12. **Analytics** — a pointer to `analytics.md`, not a duplicate.
13. **Scaling** — the signal/threshold/action table and the capacity arithmetic.
14. **Platform constraints** — deployment facts, including the `NODE_TLS_REJECT_UNAUTHORIZED` note.
15. **Decisions** — the ADR index, one line each.
16. **Traceability** — `REQ-###` to endpoint, table or job. Generated by `coverage-report.mjs`.

Every factual claim carries a `REQ-###` or a node id. A section with no citations is a section somebody invented.

## 2. `openapi.yaml`

OpenAPI 3.1. Not the runtime spec — Elysia generates that from the route schemas — but the **target contract** the frontend can build against before any code exists. That is the point: it unblocks the frontend on day one.

Requirements:

- every endpoint from the table, with `operationId`;
- request and response schemas including **every error variant**, as enumerated string literals;
- `components.schemas` for shared entities, referenced rather than copy-pasted;
- security schemes declared (the `x-init-data` header, bearer);
- a `description` on every operation naming the `REQ-###` it implements.

Validate that it parses before handing it over. A malformed spec is worse than none, because the frontend generates a client from it.

---

## 3. `schema.draft.ts`

Real Drizzle code, not prose. A draft that compiles is reviewable; a description of a schema is an argument waiting to happen.

Includes: tables with explicit column types and nullability, enums, foreign keys with `onDelete`, unique constraints (each with a comment naming the invariant it enforces), check constraints, and indexes (each with a comment naming the query it serves).

Mark anything uncertain with `// TODO(Q-012): ...` rather than picking silently.

Format in [analytics.md](analytics.md). Lands in the repo as `docs/analytics.md` and becomes the single source of truth, under the standing "update it in the same commit" rule.

## 5. `BACKLOG.md`

Sequenced, dependency-ordered, sized. One row per task:

| ID | Task | Depends on | Size | Requirement | Hotspot |
| --- | --- | --- | --- | --- | --- |
| T-001 | Bootstrap: config, db client, migrations, health | — | S | REQ-001 | — |
| T-014 | Box purchase endpoint + concurrency test | T-009, T-011 | M | REQ-014 | H-003 |

Sizes are S/M/L — three buckets, because finer estimates at this stage are false precision. Ordering rules:

1. Foundation first: config, database, migrations, health, auth, telemetry.
2. Then the entities other things depend on.
3. Then features, ordered by Figma `devStatus` — screens marked ready-for-dev are what the team intends to ship first, which beats your own guess at priority.
4. Cross-cutting concerns (rate limiting, admin panel) after the domain is stable.

Include the infrastructure tasks that are easy to forget and always block someone: adding a new sealed secret to CI, creating the S3 bucket, registering the webhook, creating the analytics project for staging.

**Every `H-###` produces its own backlog item** containing the concurrency test. Not "implement purchase", but "implement purchase **with** the concurrency test from H-003". A guard without a test is a guard that will be refactored away.

## Landing in the repo

| Artefact | Destination |
| --- | --- |
| `BACKEND-PLAN.md` | `docs/backend-plan.md` |
| `analytics.md` | `docs/analytics.md` |
| `openapi.yaml` | `docs/openapi.yaml` |
| endpoint table and patterns | `AGENTS.md` / `CLAUDE.md` — template `templates/AGENTS.md` |
| `BACKLOG.md` | the issue tracker, one item per row |
| ADRs | `docs/adr/` |

The `AGENTS.md` endpoint table carries the standing instruction to keep it current, because it is the first thing every future agent session reads — and a stale endpoint table actively misleads.
